## 修复「拖动播放进度条崩溃」（17:00）
- 用户报障：拖进度条时 iPlayer 意外退出。诊断报告中三份 .ips（16:19/16:21/16:23）均为 SIGABRT，faulting thread = tokio-rt-worker。
- 定位：release 版触发 panic 只有一行 `panic in a function that cannot unwind`；把 `[profile.release]` 临时改为 `strip=false, debug=1` 后拿到完整符号栈 → `tauri::protocol::asset::get` → `wry::url_scheme_handler::start_task::response` → `WKURLSchemeTask::didReceiveData/didReceiveResponse` → objc2 把 WebKit 的 `NSInternalInconsistencyException("This task has already been stopped")` 变成 panic → abort。
- 复现：前端临时注入自测钩子（自动打开 /tmp/ipvideos/demo.mkv 并用 PointerEvent 全程拖动进度条）+ 临时 `_dbg` 命令；**清空 app_cache_dir/playback 缓存**后 3/3 稳定复现，缓存命中时不易触发。
- 修复：`objc2` 加 `catch-all` feature（ObC 异常 → 可捕获 Rust panic）+ 移除 `panic = "abort"`（改 `panic = "unwind"`）+ `lib.rs` 加 panic hook 静音这条无害消息。修复后同场景 3/3 存活，两轮拖动全部完成，无新崩溃报告；7.89 MiB 发布版已构建并启动。
- 清理：自测钩子与 `_dbg` 命令已全部移除（grep 校验为 0 残留），Cargo.toml 中加了「不要加回 panic=abort」的注释。

## 多平台打包命令（17:40）
- 用户要 Windows 安装包 + macOS 通用版（Intel + Apple Silicon）的打包命令。
- package.json 新增脚本：`build:mac`（aarch64 + app,dmg）、`build:mac:universal`（universal-apple-darwin + app,dmg）、`build:win`（x86_64-pc-windows-msvc + nsis,msi）、`build:win:cross`（加 `--runner cargo-xwin`，只能出 NSIS）。用 `--bundles` 覆盖 tauri.conf.json 里 `targets:["app"]` 的限制，无需改配置。
- 关键结论：
  - MSI 只能在 Windows 上构建（WiX 仅 Windows）；NSIS 可在 macOS/Linux 交叉编译，需 `brew install nsis llvm` + `cargo install cargo-xwin`，官方标注实验性、不支持签名。
  - 通用包要求 sidecar 也是通用二进制，Tauri 按目标三元组找文件（通用构建对应 `-universal-apple-darwin`）。
  - 本项目 Rust 代码已具备 Windows 分支（`#[cfg(target_os="windows")]`：CREATE_NO_WINDOW / explorer / cmd start），编译层面无障碍。
  - **未解决的缺口**：src-tauri/binaries 只有 aarch64-apple-darwin 的两个 Homebrew 动态链接二进制（依赖 /opt/homebrew），既不能分发也不能跑 x86_64；Windows sidecar 完全缺失；本机只装了 aarch64-apple-darwin 一个 Rust target。scripts/fetch-sidecar.mjs 也不支持 universal 三元组。
  - 本机 bundle_dmg.sh 不稳定（DMG 曾挂起），本地出 dmg 有风险。
