# 2026-10-07 — iPlayer 工作日志

## 静态 sidecar 搞定：包从 8 MB → 94 MB，且真正可分发了

昨天 `fetch:sidecar` 从 GitHub 下载全失败，只能 fallback 拷本机 Homebrew 的**动态链接** ffmpeg
（依赖 `/opt/homebrew/Cellar/ffmpeg/9.0.2/lib/` 下 36 个 dylib，拷到别的机器必挂）。
今天用户给 git 加了代理，重试成功。

### 关键：代理端口

- `git config --global http.proxy` = `socks5://127.0.0.1:7897`（Clash/Mihomo 默认 SOCKS 口）。
- ⚠️ 环境里本来就有 `HTTP_PROXY=http://127.0.0.1:50652`（WorkBuddy 内部代理），
  **它下不动 GitHub**（`http=000` / curl exit 56）。所以不能靠 env，必须显式 `--proxy`。
- 实测：`socks5h://127.0.0.1:7897` 最快（首片 1.9s），`socks5://` 也行（5.2s），
  `http://127.0.0.1:7890` 那个口**没监听**（exit 7）。
- 下载时**用 `socks5h`**（DNS 也走代理），比 `socks5` 快。
- `npm run fetch:sidecar` 仍然会失败——Node 的 `fetch`/undici **默认不读 proxy 环境变量**，
  也不会用 git 的 proxy 配置。所以直接 curl 手动下更省事：

```bash
BASE="https://github.com/eugeneware/ffmpeg-static/releases/download/b6.1.1"
for a in ffmpeg-darwin-arm64 ffprobe-darwin-arm64 ffmpeg-darwin-x64 ffprobe-darwin-x64; do
  curl -sL --proxy socks5h://127.0.0.1:7897 -o "$a" "$BASE/$a"
done
```

下载结果（共 ~243 MB，花了 4m50s）：
`ffmpeg-darwin-arm64` 45.5MB / `ffprobe-darwin-arm64` 45.5MB /
`ffmpeg-darwin-x64` 78.9MB / `ffprobe-darwin-x64` 78.8MB。

### 坑：curl 下下来没有执行位

`curl -o` 写出来是 644，直接跑会 `permission denied`。必须 `chmod 755`。
（`fetch-sidecar.mjs` 里有 `chmodSync(dest, 0o755)`，手动下载时得自己补。）

### 验证结论

- `otool -L` 只剩 `/usr/lib` 和 `/System/Library` → **真静态，可分发了**。
- 注意 `otool -L` 每行**以 tab 开头**，所以 `grep -v "^/usr/lib"` 这类锚定过滤会失效，
  要么用 `awk '{print $1}'` 先取字段，要么别用 `^`。
- 版本是 **ffmpeg 6.0**（b6.1.1 这个 tag 里其实就是 6.0），比本机 Homebrew 的 9.0.2 老。
  能力核对过，app 要用的全都有：
  - 视频编码：`libx264` `libx265` `libvpx` `libvpx-vp9` `h264_videotoolbox` `libsvtav1`
  - 音频解码：`ac3` `eac3` `dca`(DTS) `aac` `mp3` `flac` `opus` `vorbis`
  - 音频编码：`aac` `libopus` `libmp3lame` `flac` `pcm_s16le`
  - 容器：matroska / mov / mp4 / webm / mpegts / avi / flv / asf / ac3 / image2
- 用**包内**的 ffmpeg 跑了一遍 app 实际发的 remux 命令
  （`-map "0:v:0?" -map "0:a:0?" -sn -dn -c:v copy -c:a copy`）：
  8 秒 MKV+AC-3 → 0.102s，产物 `h264 + ac3,6` ✅。
- `npm run build` → 43s，`iPlayer.app` **94.27 MiB**。
  `Contents/MacOS/{iplayer(6.9M), ffmpeg(43M), ffprobe(43M)}`；只打进了 arm64 那两个，
  x64 的（75MB×2）没进包 —— 因为默认只按 host triple 打包。
- 启动冒烟通过。注意 `osascript -e 'quit app "iPlayer"'` 对它**无效**（进程还在），
  得直接 `kill <pid>`。

### sidecar 解析顺序（读 `ffmpeg.rs::candidates` 确认，别再猜）

1. `current_exe().parent().join(name)` —— 打包后就是 `Contents/MacOS/ffmpeg`
2. （app bundle 的 Resources 位置）
3. `src-tauri/binaries/{name}-{TARGET_TRIPLE}`，再退到 `{name}`
4. 系统 PATH + `/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin`

每个候选都要过 `works()`（真跑一次）才采用，结果进 `OnceLock` 缓存。

`resource path binaries/ffmpeg-aarch64-apple-darwin doesn't exist`）。

## GPUI 迁移：可行性验证（Spike）完成

用户决定：**前端渲染改用 GPUI（gpui-kit），纯原生 ffmpeg 解码上屏，原地替换现有前端**。

### 关键侦察结论
- `gpui-kit 0.7.1` 在 crates.io，pin crates.io 上的 **`gpui-pre 0.3.8`**（Zed GPUI 官方快照包，2026-10-05 更新），不需要 git 依赖 Zed。本机 Rust 1.99 + macOS 27 + edition 2024 编译通过（首次全量 24s，增量 1s）。
- `use gpui_kit::*;` 即 GPUI 本体（re-export）；组件在 `gpui_kit::component::*`。
- 组件够用：title_bar/sidebar/input/switch/slider/button/icon/tab/dialog/sheet/notification/progress/table/virtual_list/resizable/theme/plot。
- **没有视频/音频组件**；`gpui-wry`（内嵌 WebView）存在但用户选了纯原生路线。

### Spike 实测（/tmp/gpui-probe）
- 路径：ffmpeg 子进程 `-f rawvideo -pix_fmt bgra` → 管道 → `image::ImageBuffer<Rgba<u8>,Vec<u8>>::from_raw`（只是类型标签，字节不动）→ `RenderImage::new(SmallVec::from_vec(vec![Frame::new(buf)]))` → `img(ImageSource::Render(arc))`。
- **实测 1080p25 H.264 解码+缩放到 640x360 = 250 fps（10× 实时）**；限速播放时解码 25.1fps、渲染 140fps 持续不断。
- 字节序已验证：ffmpeg `bgra` 输出 `B,G,R,A`，GPUI `RenderImage` 文档要求 BGRA，吻合，无需转换。

### 三个必踩的坑（勿回退）
1. **`cx.notify()` 不会唤醒平台帧源**——异步任务里 notify 后窗口不重绘（实测 rendered 卡在 2）。视频播放必须用 `window.request_animation_frame()`（GPUI 文档原话点名 video player）；它走 `on_next_frame` → `platform_window.schedule_frame()` + `invalidator.wake_platform()`。
2. **`WindowOptions::default()` 不行**——必须给 `window_bounds: Some(WindowBounds::centered(size(px(..),px(..)), cx))`，否则窗口异常且帧循环不跑。
3. **要 `cx.activate(true)`**，否则应用不前置。
- 纹理复用：`RenderImage::new` 每次分配新 `ImageId`；把当前帧存成 `Arc<RenderImage>` 只在新帧到来时替换，其余 render 复用同一 Arc → 同 ImageId 不重复上传。
- `Context::spawn(async move |this: WeakEntity<T>, cx: &mut AsyncApp| { this.update(cx, |_, cx| ...) })` 可用。
- image crate 版本必须 0.25.10（与 gpui-pre 一致，Frame 类型才相同）。
- 无法截图验证窗口内容：gpui 无 capture_screenshot，`scap` 需录屏权限（沙箱没有）；用 stderr 统计 + 首帧落 PNG 离线核对代替。

### 迁移计划（已与用户对齐方向）
- 阶段1 脚手架：仓库改为纯 Rust GPUI 应用（去 Tauri/去 src/*.js），复用 media.rs 探测 + ffmpeg.rs sidecar 定位。
- 阶段2 播放内核：video 管道（解码→上屏）+ seek（kill 后 -ss 重开，沿用 stream.rs 思路）+ 音频输出（cpal/rodio）+ A/V 同步（音频钟为主）。
- 阶段3 UI 全量：侧栏/文件列表/控制条/弹窗/主题（黑白单色规范沿用）。
- 阶段4 收尾：打包、删旧代码。
- 纯原生后 10-bit/老编码都能直接播，remux/transcode/stream.rs 整套机制可退役（media.rs 的 ffprobe 探测仍要保留）。
